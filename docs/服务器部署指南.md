## 2. 服务器初始化

首次部署时需要安装 Docker：

```bash
sudo apt update
sudo apt install -y git ca-certificates curl gnupg

sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
```


## 9. 域名与 HTTPS

已配置域名解析及 ICP 备案：

```text
customprint.icu
www.customprint.icu
```

HTTPS 由容器内 nginx 直接处理（`nginx/default.conf`），证书通过 Let's Encrypt 免费获取。

### 首次申请证书

```bash
# Ubuntu/Debian 系统
sudo apt install -y certbot
sudo certbot certonly --standalone -d customprint.icu -d www.customprint.icu
```

证书存放在 `/etc/letsencrypt/live/customprint.icu/`，容器通过只读挂载使用。

### 证书自动续期

certbot 安装后自动配置 systemd timer，续期后需 reload 容器 nginx：

```bash
# 添加续期 hook（一次性）
echo "renew_hook = docker exec wms-print-template-nginx nginx -s reload" >> /etc/letsencrypt/renewal/customprint.icu.conf
```

## 10. 生产环境注意事项

- 替换所有 `.env` 中的敏感信息后再部署
- HTTPS 由容器 nginx 承担，证书路径 `/etc/letsencrypt` 以只读挂载
- 数据库切换前执行 `npm run migrate`
- 公开写接口前需添加鉴权
- MySQL 备份需在应用容器外配置
- 容器重启会重新执行全部迁移脚本，迁移 SQL 需保证幂等（详见 §11）

## 11. SQL 迁移编写规范

### 11.1 必须幂等

每个迁移 SQL 在重复执行时不能产生副作用。强制使用以下模式：

| 场景 | 推荐写法 |
|------|---------|
| 建表 | `CREATE TABLE IF NOT EXISTS ...` |
| 加列 | 先用 `information_schema.COLUMNS` 查是否存在，存在则跳过 |
| 加索引 | 先用 `information_schema.statistics` 查是否存在，存在则跳过 |
| 删索引 | 先用 `information_schema.statistics` 查是否存在，不存在则跳过 |
| 种子数据 | `INSERT IGNORE` 或 `INSERT ... ON DUPLICATE KEY UPDATE` |
| 字段批量插入 | 先查目标表是否已有记录，已有则跳过整段 |

**推荐模板**：

```sql
-- ✅ 推荐：加列前检查
SET @col_exists := (
    SELECT COUNT(*) FROM information_schema.COLUMNS
    WHERE table_schema = DATABASE()
      AND table_name = '目标表名'
      AND column_name = '目标列名'
);
SET @sql := IF(@col_exists = 0,
    'ALTER TABLE 目标表名 ADD COLUMN 目标列名 类型',
    'SELECT "column already exists, skip" AS msg'
);
PREPARE stmt FROM @sql;
EXECUTE stmt;
DEALLOCATE PREPARE stmt;
```

**禁止操作**：

| 禁止 | 说明 |
|------|------|
| 裸 `UPDATE` / `DELETE` | 重复执行会修改已有数据 |
| 裸 `DROP TABLE` / `DROP COLUMN` | 破坏性操作，需人工评审 |
| 不含 `IF NOT EXISTS` 的 `CREATE TABLE` | 重复执行报错 |
| 无条件 `ALTER TABLE ADD COLUMN` / `ADD INDEX` | 重复执行报错 |

### 11.2 提交前验证

```bash
# 本地跑两次，第二次应全部 skip
cd backend && node scripts/run-migration.js   # 第一次：应用新迁移
node scripts/run-migration.js                  # 第二次：0 new, N skipped
```

## 12. `_migrations` 追踪表保护

迁移追踪依赖 `_migrations` 表。该表丢失会导致全部迁移重跑（虽然每步都幂等，但 `ON DUPLICATE KEY UPDATE` 可能覆盖用户修改）。

**防护措施**：

- MySQL 数据卷已持久化（`docker-compose.yml` → `mysql_data` 卷）
- **禁止**手动删除或清空 `_migrations` 表
- **禁止**删除 `mysql_data` Docker 卷
- 迁移 SQL 自身必须幂等（见 §11），作为第二道防线

## 14. 回滚预案

部署后出现严重问题时：

```bash
# 方式一：服务器上回滚到上一个 commit
ssh root@47.113.118.74 \
  "cd /opt/wms-print-template-center && git reset --hard HEAD~1 && docker compose up -d --build"

# 方式二：本地回滚后重新部署
git revert HEAD --no-edit && git push && ./scripts/deploy-server.sh
```

> **注意**：迁移 SQL 是单向的（DDL 不可逆），回滚代码不会回滚数据库结构。如需回滚数据库结构，需手动编写反向迁移 SQL。
