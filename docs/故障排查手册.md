# 故障排查手册

> **何时查看**：遇到任何系统异常时优先查看 / 不确定问题属于哪个领域时从这里开始

本文档记录打印模板中心常见问题的定位顺序和处理方式。先确认现象，再按对应章节排查，避免直接改数据库或生产配置。

---

## 1. 本地项目启动失败

### 1.1 `Local MySQL is not reachable on 127.0.0.1:3306`

含义：`./scripts/dev-local.sh` 检测不到本机 MySQL。

排查步骤：

```bash
# 检查 3306 端口是否可连接
nc -z 127.0.0.1 3306
```

处理方式：

1. 打开 Docker Desktop。
2. 启动本机已有 MySQL 容器，容器名按本机实际情况替换：

```bash
docker start mysql
```

3. 确认端口映射包含 `127.0.0.1:3306 -> 3306`。
4. 重新执行：

```bash
./scripts/dev-local.sh
```

### 1.2 前端页面打不开

确认脚本是否输出前端地址：

```text
App: http://127.0.0.1:5173
```

如果没有输出，说明前端服务没有启动成功。进入 `frontend/` 单独启动查看报错：

```bash
npm --prefix frontend run dev -- --host 127.0.0.1
```

### 1.3 后端健康检查失败

访问：

```text
http://127.0.0.1:3001/api/v1/health
```

如果不通，单独启动后端查看报错：

```bash
npm --prefix backend run dev
```

重点检查：

- MySQL 是否已启动。
- `backend/.env` 中 `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME` 是否正确。
- 端口 `3001` 是否被其他进程占用。

## 2. 数据库迁移失败

迁移命令：

```bash
npm --prefix backend run migrate
```

### 2.1 数据库连接失败

重点检查：

- 本地开发：`backend/.env` 中的 `DB_*`。
- Docker 部署：根目录 `.env` 中的 `MYSQL_DATABASE`、`MYSQL_USER`、`MYSQL_PASSWORD`。
- 服务器部署：MySQL 容器是否健康。

查看 Docker 服务：

```bash
docker compose ps
docker compose logs -f mysql
docker compose logs -f backend
```

### 2.2 Docker 后端无法连接 MySQL

当前 `docker-compose.yml` 中，后端使用 `MYSQL_USER` / `MYSQL_PASSWORD` 对应的普通用户连接数据库。

如果生产服务器的 MySQL 数据卷是旧版本初始化的，可能没有创建该普通用户。需要在服务器确认该用户存在，并拥有 `wms_print_template` 数据库权限。

### 2.3 迁移重复执行是否安全

迁移脚本通过 `_migrations` 表记录已执行文件。正常情况下重复执行会显示：

```text
Migration completed for database wms_print_template: 0 new, 5 skipped
```

新增迁移 SQL 必须保持幂等，避免容器重启时重复执行失败。

## 3. 登录和权限问题

### 3.1 登录失败

检查：

- 用户名和密码是否正确。
- `sys_user.status` 是否为启用状态。
- 后端 `/api/v1/auth/login` 是否返回业务错误。

常用预置账号见 [功能清单 - 权限说明](功能清单.md#5-权限说明)。

### 3.2 菜单或按钮权限不生效

权限变更后，用户需要重新登录。系统登录时会返回权限码和菜单树，前端会把它保存到本地状态中。

排查顺序：

1. 确认 `sys_menu.permission_code` 是否正确。
2. 确认角色已绑定对应菜单或按钮。
3. 退出登录后重新登录。
4. 直接访问页面 URL，确认是否跳转 `/403`。

新增页面或按钮时，按 [权限系统开发规范](权限系统开发规范.md) 同步迁移种子、前端路由和按钮权限。

## 4. 模板启用失败

模板启用前会执行 DSL 校验。常见失败原因：

- 画布没有元素。
- 动态文本没有绑定字段。
- 条码或二维码没有绑定字段。
- 元素绑定了当前模板类型不存在的字段。
- 元素完全超出画布。

处理方式：

1. 进入模板设计器。
2. 查看底部「校验结果」。
3. 修正错误项后保存。
4. 返回模板列表重新启用。

如果修改 DSL 校验规则，必须同步更新前端和后端校验逻辑，并运行 `dslParity.test.js`。

## 5. PDF 和打印问题

### 5.1 PDF 中文乱码或生成失败

后端使用项目内字体生成中文 PDF。默认字体路径来自：

```text
backend/fonts/ArialUnicode.ttf
```

生产环境可通过 `PDF_CJK_FONT_PATH` 覆盖。通常无需设置。

排查步骤：

1. 确认字体文件存在。
2. 查看后端日志是否有 `CJK font registration failed`。
3. 确认容器内字体路径可访问。

### 5.2 打印失败：模板未启用

只有 `enabled` 状态模板可以打印。处理方式：

1. 进入模板列表。
2. 确认模板状态为「启用」。
3. 如果启用失败，按「模板启用失败」章节处理。

### 5.3 打印失败：业务类型与模板类型不一致

业务数据类型必须与模板类型一致，例如：

- 库位数据只能使用库位模板。
- 容器数据只能使用容器模板。
- 商品数据只能使用商品模板。

### 5.4 打印份数或页数超限

当前限制：

- 打印份数：`1-1000`
- 总页数：`rows.length * copies <= 200000`

如果超限，减少选择的数据条数或打印份数。

### 5.5 PDF 下载很慢

大批量打印会触发条码、二维码生成。当前后端已使用流式输出和条码/二维码预渲染缓存，但超大任务仍可能耗时较长。

建议：

- 分批选择业务数据。
- 优先使用较少二维码/条码元素的模板。
- 避免一次性打印接近上限的页数。

## 6. Excel 导入问题

导入按钮不可见：说明没有 `business:import` 权限，联系管理员分配后重新登录。

上传失败：常见原因包括文件非 `.xlsx`、超过 5MB、表头不匹配、必填字段为空、唯一性字段重复等。

完整规则、失败原因及处理方式见 [数据导入规范](数据导入规范.md)。

## 7. 生产部署问题

### 7.1 服务未启动

查看容器状态：

```bash
docker compose ps
```

查看日志：

```bash
docker compose logs -f backend
docker compose logs -f frontend
docker compose logs -f nginx
docker compose logs -f mysql
```

### 7.2 HTTPS 访问失败

检查：

- 服务器安全组是否开放 `80/tcp` 和 `443/tcp`。
- `/etc/letsencrypt/live/customprint.icu/` 证书是否存在。
- `nginx/default.conf` 中证书路径是否匹配。

### 7.3 部署脚本失败

本地执行：

```bash
./scripts/deploy-server.sh
```

重点检查：

- `SSH_KEY` 文件是否存在。
- 服务器目录 `/opt/wms-print-template-center` 是否存在。
- 服务器 Git 分支是否能 `pull --ff-only`。
- Docker Compose 是否可用。

## 8. 排查后的处理原则

- 不直接删除生产数据。
- 不手动修改表结构，数据库结构变更必须新增迁移文件。
- 不把真实 `.env`、数据库密码、证书私钥写入文档或提交。
- 本地测试产生的数据要按 [测试指南](测试指南.md) 清理。
