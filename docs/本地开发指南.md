# 本地开发指南

> **何时查看**：首次搭建本地开发环境时 / 本地启动失败时 / 配置环境变量时 / 新增开发者 onboarding 时

本文档说明如何在本地启动 打印模板中心项目进行开发调试。

## 1. 启动 MySQL

本项目本地开发复用 Docker Desktop 中已有的 MySQL 服务。

### 自动启动（推荐）

```bash
# 启动 Docker Desktop（如果未运行）
open -a "Docker Desktop"

# 等待 Docker 就绪后启动已有 MySQL 容器（mysql 为示例容器名）
docker start mysql
```

### 手动启动

在 Docker Desktop 中启动已有 MySQL 容器。

当前本机约定：

```text
Host: 127.0.0.1
Port: 3306
Database: wms_print_template
```

DataGrip 只作为数据库连接工具使用，它不会启动 MySQL 服务。

## 2. 检查本地环境变量

项目根目录需要有本地 `.env` 文件，`./scripts/dev-local.sh` 会检查该文件是否存在：

```bash
cd /Users/l/Documents/Wms_Print/wms-print-template-center
cp .env.example .env
```

如果已经存在 `.env`，不要覆盖。根目录 `.env.example` 主要提供 Docker Compose 使用的 `MYSQL_*` 字段；后端直连本地 MySQL 时使用 `DB_*` 字段，可参考 `backend/.env.example` 配置到 `backend/.env`：

```env
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD= # 填写你的本地 MySQL 密码
DB_NAME=wms_print_template
CORS_ORIGIN=http://127.0.0.1:5173
```

`.env` 已在 `.gitignore` 中，不允许提交。

`backend/.env` 同样不允许提交。若数据库迁移连接失败，优先检查 `backend/.env` 中的 `DB_PASSWORD`、`DB_NAME` 是否与本机 MySQL 一致。

## 3. 启动本地项目

确认 MySQL 已运行后：

```bash
cd /Users/l/Documents/Wms_Print/wms-print-template-center
./scripts/dev-local.sh
```

脚本会执行：

```text
1. 检查 127.0.0.1:3306 是否可连接
2. 执行数据库迁移
3. 启动后端热重载服务：http://127.0.0.1:3001
4. 启动前端 Vite 服务：http://127.0.0.1:5173
```

## 4. 访问本地服务

脚本启动后会输出服务地址，需要手动打开浏览器或 DataGrip：

```bash
open http://127.0.0.1:5173
open -a "DataGrip" "jdbc:mysql://127.0.0.1:3306/wms_print_template"
```

本地服务地址：

| 服务 | 地址 |
|------|------|
| 前端页面 | http://127.0.0.1:5173 |
| 后端健康检查 | http://127.0.0.1:3001/api/v1/health |
| MySQL | 127.0.0.1:3306 |

## 5. 日常开发流程

推荐流程：

```text
本地修改代码
-> 在 http://127.0.0.1:5173 验证
-> 必要时重启服务（见 5.1）
-> ./scripts/check-before-push.sh
-> git commit / git push
-> ./scripts/deploy-server.sh
```

不要为了看页面效果频繁部署服务器。服务器只作为最终验收环境。

### 5.1 服务重启规范

**何时需要重启**：以下变更不会自动热更新，必须手动重启对应服务才能生效：

| 变更类型 | 需重启的服务 | 原因 |
|----------|-------------|------|
| 数据库迁移（新增 migration SQL 文件） | **后端** | 迁移脚本在启动时执行，后端 `--watch` 不监听 SQL 文件 |
| 新增/修改 npm 依赖 | **后端 / 前端** | 依赖安装在启动时加载 |
| 环境变量变更（`.env`） | **后端** | 环境变量在进程启动时读取 |
| 后端 `src/` 目录外的文件（如 `scripts/`） | **后端** | `node --watch` 仅监听 `src/` |

> **注意**：后端使用 `node --watch` 监听 `src/` 目录，前端使用 Vite HMR，绝大多数代码变更会自动热更新，无需手动重启。

**重启命令**：

```bash
# 方式一：一键重启（推荐）
./scripts/restart-dev.sh

# 方式二：手动分别重启
# 停止服务
lsof -ti :3001 | xargs kill  # 停止后端
lsof -ti :5173 | xargs kill  # 停止前端

# 启动服务
cd backend && nohup npm run dev > /tmp/wms-backend.log 2>&1 &
cd frontend && nohup npm run dev -- --host 127.0.0.1 > /tmp/wms-frontend.log 2>&1 &
```

**验证重启成功**：

```bash
# 检查端口是否在监听
lsof -i :3001 -i :5173 | grep LISTEN

# 后端健康检查
curl http://127.0.0.1:3001/api/v1/health
```

### 5.2 keep-alive 缓存注意事项

`AppLayout.vue` 使用 `<keep-alive>` 缓存所有页面组件。页面切换时不会重新挂载（`onMounted` 不触发），只触发 `onActivated`。

**问题场景**：从 A 页面修改配置 → 切换到 B 页面时，B 页面数据不会自动刷新。

**修复模板**：需要在 keep-alive 组件中添加 `onActivated` 钩子：

```javascript
import { onActivated } from 'vue';

onActivated(() => {
  fetchData();  // 重新拉取最新数据
});
```

**检查方法**：修改完其他页面的配置后切回来，确认数据自动刷新，**不依赖手动刷新浏览器**。

## 6. 预提交检查

提交前执行：

```bash
./scripts/check-before-push.sh
```

该脚本会检查：

- 后端 JavaScript 语法
- 前端 production build
- 常见敏感信息模式
- 是否误提交 `.env` 文件

## 7. 本地 Docker 启动（可选）

验证生产环境 Docker 配置（需先准备本地证书，否则 nginx 容器无法启动）：

```bash
# 生成本地自签名证书
mkdir -p /etc/letsencrypt/live/localhost
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/letsencrypt/live/localhost/privkey.pem \
  -out /etc/letsencrypt/live/localhost/fullchain.pem \
  -subj "/CN=localhost"

cp .env.example .env
docker compose up -d --build
```

默认访问地址：

```text
前端入口：https://127.0.0.1（浏览器需跳过证书警告）
后端健康检查：https://127.0.0.1/api/v1/health
MySQL：127.0.0.1:3306
```

## 8. 常见问题

**问题：Local MySQL is not reachable on 127.0.0.1:3306**

处理方式：

```text
1. 打开 Docker Desktop
2. 启动已有 MySQL 容器（容器名按本机实际情况替换）
3. 确认端口映射包含 3306 -> 3306
4. 重新执行 ./scripts/dev-local.sh
```

**问题：DataGrip 可以连接，但后端不能连接**

重点检查 `.env` 中的 `DB_PASSWORD`、`DB_NAME` 是否与 DataGrip 配置一致。
