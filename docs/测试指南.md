# 测试指南

本文档说明项目的测试文件结构与运行方式。

> **⚠️ 强制约束**：执行测试后必须清理测试数据，不得修改/删除既有本地数据。详见下方"测试数据清理"。

## 后端测试 (`backend/tests/`)

| 文件 | 测试范围 |
|------|----------|
| `api.test.js` | API 接口集成测试 |
| `dsl.test.js` | DSL 模板校验逻辑 |
| `dslParity.test.js` | DSL 前后端一致性 |
| `env.test.js` | 环境变量加载 |
| `pdfLayout.test.js` | PDF 布局生成 |
| `recordService.test.js` | 业务记录 CRUD 服务 |

### 运行测试

```bash
cd backend

# 运行全部测试
npm test

# 运行数据库相关测试（需配置 .env.test）
RUN_DB_TESTS=1 npm run test:db
```

## 测试数据清理（强制）

测试脚本会直接操作本地开发数据库，执行完毕后**必须**清理所有测试产生的数据。

### 影响范围

| 表 | 测试产生的数据 | 不得操作 |
|----|--------------|---------|
| `business_record` | 测试导入/创建的记录 | 既有业务数据 |
| `print_template` | 测试创建的模板 | 既有模板 |
| `print_business_module` | 测试创建的模块（TST_、DEL_、RST_ 等前缀） | LOCATION/CONTAINER/PRODUCT 默认模块 |
| `print_field_dict` | 测试创建的字段 | 现有模块的字段 |
| `sys_user` | 测试创建的用户/角色 | admin 及既有用户 |

### 清理方式

`api.test.js` 已内置全局 `after()` 钩子自动清理。如需手动清理：

```sql
-- 删除测试模块（以特定前缀命名的模块）
DELETE FROM business_record WHERE module_code REGEXP '^[A-Z]{2,4}_MR[0-9A-Z]+$';
DELETE FROM print_field_dict WHERE module_code REGEXP '^[A-Z]{2,4}_MR[0-9A-Z]+$';
DELETE FROM print_business_module WHERE module_code REGEXP '^[A-Z]{2,4}_MR[0-9A-Z]+$';

-- 删除测试模板
DELETE FROM print_template WHERE template_code LIKE 'TPL_PRINT_MR4%';
```
