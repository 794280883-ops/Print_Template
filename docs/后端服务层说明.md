# 后端服务层说明

> **何时查看**：新增 service 时 / 排查打印 PDF 失败时 / 理解请求全链路数据流时 / 新增中间件或工具函数时

## 三层架构

```
routes → controllers → services → repositories → MySQL
```

| 层级 | 职责 | 示例 |
|------|------|------|
| **routes/** | 路由注册 + 权限中间件绑定 | `templateRouter.get("/templates", requirePermission("template:view"), ...)` |
| **controllers/** | 请求参数提取、校验、响应格式化 | `templateController.listTemplates(req, res)` |
| **services/** | 业务逻辑、编排多个repository | `templateService.listTemplates(filters)` |
| **repositories/** | 原生SQL查询、数据库交互 | `templateRepository.listTemplates(filters)` |

## 关键服务

### schemaService — 运行时Schema编译

`services/schemaService.js` — 核心service，负责：
- 编译模块元数据：从 `print_business_module` + `print_field_dict` 读取
- 生成前端表单配置：根据字段类型/必填/可搜索属性动态生成
- 生成搜索配置：仅 `searchable=1` 的字段出现在搜索区
- 编译数据校验规则：用于新增/编辑业务数据时的后端校验

新增自定义业务模块后，无需修改任何后端代码，schemaService 自动支持新模块。

### recordService — 统一业务数据CRUD

`services/recordService.js` — 所有业务类型的增删改查统一入口：
- `searchRecords(query)` — 支持 keyword 批量模糊查询 + fieldFilters 精确查询
- `createRecord(payload)` — 校验必填 + 唯一性（is_unique字段）
- `updateRecord(bizType, bizCode, payload)` — 优先按 `_dbId` 精确更新，未传 `_dbId` 时兼容按编码更新
- `deleteRecord(bizType, bizCode, payload)` — 优先按 `_dbId` 精确删除，未传 `_dbId` 时兼容按编码删除
- `deleteRecords(bizType, payload)` — 按数据库主键 `ids` 批量删除，不再按编码批量删除

### printService + pdfGenerator + pdfLayout — PDF生成

- `services/printService.js` — 校验打印模板、生成打印日志、构造批量打印业务编码摘要
- `services/pdfLayout.js` — 解析 `print_template_element`，计算元素坐标、样式、字体
- `services/pdfGenerator.js` — 调用 PDFKit 生成PDF，集成 bwip-js（条码）+ qrcode（二维码），支持流式输出

### authService — 认证鉴权

- `login(username, password)` — 验证密码 → 生成JWT → 查询权限 → 返回token+permissions+menus
- `verifyToken(token)` — JWT验证
- `getPermissionCodesForUser(userId)` — 遍历用户角色获取所有权限码

## 中间件

| 文件 | 函数 | 说明 |
|------|------|------|
| `auth.js` | `requireAuth` | JWT验证，注入 `req.user` 和 `req.permissions` |
| `auth.js` | `requirePermission(code)` | 权限验证（支持单个或数组，函数动态判断） |
| `asyncHandler.js` | `asyncHandler` | 捕获异步错误统一抛给errorHandler |
| `errorHandler.js` | `errorHandler` | 统一错误响应格式 |

## 工具函数

| 文件 | 导出 | 说明 |
|------|------|------|
| `utils/response.js` | `sendSuccess(res, data)` | 统一成功响应 `{ code:0, message:"success", data }` |
| `utils/response.js` | `appError(message, code, status)` | 生成业务错误 |
| `utils/dsl.js` | DSL模板元素校验函数 | 验证模板元素的字段绑定、位置、尺寸等 |

### 打印请求完整数据流 (POST /api/v1/print/pdf)

```
客户端 POST /api/v1/print/pdf
  Body: { templateId, businessType, rows[], copies }
       │
       ▼
┌──────────────────────────────────────────────────────────────┐
│ printRouter.post("/print/pdf", requirePermission)            │
│   → printController.downloadPdf(req, res)                    │
└──────────────────────┬───────────────────────────────────────┘
                       │
                       ▼
  ① printController 参数校验
  ┌──────────────────────────────────────────┐
  │ 校验 templateId                          │
  │ 校验 rows 非空                           │
  │ 校验 copies: 1-1000                      │
  │ 校验 rows.length × copies ≤ 200000       │
  │ 设置请求/响应超时为 30 分钟              │
  └──────────────────┬───────────────────────┘
                     │
                     ▼
  ② printService.preparePrint
  ┌──────────────────────────────────────────┐
  │ templateService.getTemplate(templateId)  │
  │ 校验 template.status = enabled           │
  │ 校验 businessType = template.templateType│
  │ 创建 print_log 记录                       │
  │ 构造 businessNo 并截断至 2048 字符        │
  └──────────────────┬───────────────────────┘
                     │
                     ▼
  ③ printController 设置 PDF 响应头
  ┌──────────────────────────────────────────┐
  │ Content-Type: application/pdf            │
  │ Content-Disposition: attachment          │
  │ Transfer-Encoding: chunked               │
  │ X-Print-Log-Id: {logEntry.id}            │
  └──────────────────┬───────────────────────┘
                     │
                     ▼
  ④ pdfGenerator.generateTemplatePdf
  ┌──────────────────────────────────────────┐
  │ 解析 print_template_element JSON         │
  │ 调用 pdfLayout.js 计算元素坐标            │
  │                                          │
  │ for each element:                        │
  │   ├─ text     → 计算坐标(x,y,w,h)         │
  │   ├─ dynamic  → 计算坐标 + 查找字段值     │
  │   ├─ barcode  → 计算坐标 + 准备编码值     │
  │   ├─ qrcode   → 计算坐标 + 准备编码值     │
  │   ├─ line     → 计算坐标                 │
  │   ├─ rect     → 计算坐标                 │
  │   └─ checkbox → 计算坐标                 │
  │                                          │
  │ for each row in rows:                    │
  │   动态字段 → row[fieldCode]               │
  │   若值为空 → 不渲染该元素                 │
  │                                          │
  │ for each row/copy:                       │
  │   ├─ 渲染 text → doc.font().text()       │
  │   ├─ 渲染 barcode → bwip-js → doc.image()│
  │   ├─ 渲染 qrcode → qrcode → doc.image()  │
  │   ├─ 渲染 line → doc.moveTo().lineTo()   │
  │   └─ 渲染 rect → doc.rect().fill()       │
  │                                          │
  │ doc.end() → 流式输出到 res               │
  └──────────────────┬───────────────────────┘
                     │
                     ▼
         客户端收到 PDF 文件流 → 浏览器下载
```

### 业务数据 CRUD 数据流

```
POST /api/v1/business-data
  Body: { bizType, fields: {...} }
       │
       ▼
businessDataController.createRecord(req, res)
       │
       ▼
recordService.createRecord(payload)
       │
       ├── ① schemaService.compileSchema(bizType)
       │     → businessModuleRepository.getModule(moduleCode)
       │     → fieldRepository.listFields(moduleCode)
       │     返回: { recordCodeField, uniqueFields, requiredFields, allFields }
       │
       ├── ② 校验必填字段 (requiredFields)
       │     → 缺失 → throw appError(40000, "xxx必填")
       │
       ├── ③ 校验唯一性字段 (uniqueFields, withUniqueGuard)
       │     → SELECT ... FOR UPDATE 行锁
       │     → 冲突 → throw appError(40001, "组合已存在")
       │
       ├── ④ 构造 search_text
       │     → searchableFields 的值拼接
       │
       └── ⑤ recordRepository.create({
             module_code, record_code,
             record_data: JSON.stringify(fields),
             search_text
           })
           → INSERT INTO business_record
```

### 登录与权限数据流

```
POST /api/v1/auth/login
  Body: { username, password }
       │
       ▼
authController.login(req, res)
       │
       ▼
authService.login(username, password)
       │
       ├── ① userRepository.findByUsername(username)
       │     → SELECT * FROM sys_user WHERE username = ?
       │
       ├── ② 检查 user 存在且 status 启用
       │     → 不存在或停用 → throw appError(40000, "用户名或密码错误")
       │
       ├── ③ bcrypt.compare(password, user.password)
       │     → 不匹配 → throw appError(40000, "用户名或密码错误")
       │
       ├── ④ jwt.sign({ userId, username }, JWT_SECRET, { expiresIn: "24h" })
       │
       ├── ⑤ getPermissionCodesForUser(userId)
       │     → userRepository.getUserRoleIds(userId)
       │     → for each roleId: menuRepository.getPermissionCodesByRole(roleId)
       │     → 返回去重权限码数组
       │
       └── ⑥ 查询角色菜单 ID 并构建菜单树
             → userRepository.getUserRoleIds(userId)
             → menuRepository.getMenuIdsByRole(roleId)
             → menuRepository.getMenuTree(menuIds)
             → 返回前端渲染用的菜单树

返回: { token, user: { id, username, nickname }, permissions: [...], menus: [...] }
```
