# 提交前文档检查清单

> **何时查看**：每次 `git commit` / `git push` 前必看 / 不确定哪些文档需要更新时

每次 `git commit` / `git push` 前，对照此清单检查 MD 文件是否与代码一致。不一致则先更新对应文档再提交。

---

## 检查流程

```
代码变更 → 查下方对照表 → MD 不一致 → 更新 MD → 提交
```

### 执行前边界检查

| 场景 | 处理方式 |
|------|---------|
| `git diff --name-only` 返回空 | 无变更内容，跳过文档检查，直接提交 |
| 对应文档文件已不存在 | 检查 `docs/README.md` 索引是否更新；若文档被误删，从 git 历史恢复 |
| 本次为 revert/回退 commit | 同样需检查：回退的变更是否也需要回退对应文档 |

## 变更类型 → 需检查的 MD

| 代码变更 | 需检查的文档 |
|----------|-------------|
| 新增/修改/删除 API 端点 | `docs/接口文档.md` |
| 数据库表结构/字段/索引变更 | `docs/数据库设计.md` |
| 新增 migration 文件 | `docs/数据库设计.md` 迁移列表 + `docs/服务器部署指南.md` §11 |
| 新增/修改业务模块或字段 | `docs/功能清单.md` |
| 新增/修改页面 | `docs/功能清单.md` + `docs/用户操作手册.md` |
| 新增页面/按钮/权限码 | `docs/权限系统开发规范.md` |
| 新增/修改环境变量 | `docs/环境变量说明.md` |
| 部署流程变更 | `docs/服务器部署指南.md` |
| 业务流程变更 | `docs/系统流程.md` |
| 架构变更（分层/新增 service） | `docs/项目架构总览.md` + `docs/后端服务层说明.md` |
| 新增 composable/directive 等通用模块 | `docs/项目架构总览.md` |
| 测试结构/方式变更 | `docs/测试指南.md` |
| 任何功能/修复/优化变更 | `docs/变更日志.md` |

## 快速核对命令

在项目根目录执行：

```bash
# 查看本次 git 变更了哪些文件
git diff --name-only

# 根据上方对照表逐项核对
# 例如：改动了 backend/src/routes/ → 检查 docs/接口文档.md
# 例如：改动了 backend/migrations/ → 检查 docs/数据库设计.md
# 例如：改动了 *.vue → 检查 docs/功能清单.md + docs/用户操作手册.md
```

## 常见漏更新场景

| 场景 | 经常漏掉的 MD |
|------|-------------|
| 后端加了新接口 | `接口文档.md` 未追加端点 |
| 数据库加字段 | `数据库设计.md` 表结构未更新 |
| 前端加了服务或 composable | `项目架构总览.md` 未列出 |
| 任何代码改动 | `变更日志.md` 未记录 |
| 修改了文档内容 | 文档 frontmatter 中的 `last_updated` 日期未更新 |
