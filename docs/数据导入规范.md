# 数据导入规范

> **何时查看**：导入 Excel 数据前 / 导入失败排查时 / 了解重复编码处理规则时 / 配置唯一性字段时

本文档说明业务数据 Excel 导入的文件要求、字段规则、重复数据处理方式和验证建议。

---

## 1. 适用范围

业务数据导入用于「业务数据」页面，支持以下业务类型：

- `LOCATION`：库位数据
- `CONTAINER`：容器数据
- `PRODUCT`：商品数据
- 自定义业务模块

业务类型来自 `print_business_module.module_code`。字段 schema 由 `print_field_dict` 在运行时动态编译。

---

## 2. 导入入口

页面路径：

```text
左侧菜单 → 业务数据
```

操作步骤：

1. 切换到目标业务类型。
2. 点击「导入」。
3. 点击「下载导入模版」。
4. 按模板表头填写数据。
5. 上传 `.xlsx` 文件。
6. 点击「确认导入」。

后端接口：

```text
GET  /api/v1/business-data/template/:bizType
POST /api/v1/business-data/import/:bizType
```

上传接口使用 `multipart/form-data`，文件字段名为 `file`。

---

## 3. 文件要求

| 项目 | 要求 |
|------|------|
| 文件类型 | `.xlsx` |
| 文件大小 | 不超过 5MB |
| 工作表 | 使用第一个工作表 |
| 表头 | 必须使用系统导出的导入模板表头 |
| 数据行 | 至少 1 行有效数据 |

不支持：

- `.xls`
- `.csv`
- 多文件上传
- 手工改写表头名称

---

## 4. 表头和字段匹配规则

导入按字段中文名称匹配表头。例如库位模块默认表头包含：

```text
库位编码、库位前缀、排、列、层、方向标、区域仓编码、物理仓编码
```

规则：

- 表头名称来自 `print_field_dict.field_name`。
- 主键字段列必须存在，例如库位的「库位编码」。
- 未匹配到字段的列会被忽略。
- 空白行会被跳过。

字段编码不会直接出现在 Excel 表头中。

---

## 5. 必填字段规则

字段的 `is_required` 控制是否必填。

导入时：

- 主键字段必须有值。
- 必填字段为空会导致该行失败。
- 单行失败不会中断整个文件导入，其他行继续处理。

导入结果会返回：

```json
{
  "total": 4,
  "success": 3,
  "errors": [
    { "row": 5, "message": "库位编码必填" }
  ]
}
```

`row` 表示 Excel 中的实际行号。

---

## 6. 重复编码规则

003 迁移已移除 `business_record` 的编码唯一约束。

因此：

- 同一业务模块内允许导入重复业务编码。
- 业务编码字段默认不参与唯一性校验。
- 编辑、删除、批量删除按数据库主键 `_dbId` 精确定位，避免同编码误操作。

示例：

```text
LOCATION 模块中可以存在多条 locationCode = A01-001 的记录。
```

---

## 7. 唯一性字段规则

字段字典中的 `is_unique` 控制字段级唯一性校验。

当前规则：

- 只有勾选了「校验唯一性」的字段参与校验。
- 多个唯一性字段按组合校验，即所有唯一性字段值同时相同才视为重复。
- 新增、编辑、导入都会执行唯一性校验。
- 后端使用事务和 `SELECT ... FOR UPDATE` 降低并发重复写入风险。

示例：

| 字段 | 是否唯一 |
|------|----------|
| 批次号 | 是 |
| 仓库编码 | 是 |

则以下两行会冲突：

| 批次号 | 仓库编码 |
|--------|----------|
| B001 | WH01 |
| B001 | WH01 |

以下两行不会冲突：

| 批次号 | 仓库编码 |
|--------|----------|
| B001 | WH01 |
| B001 | WH02 |

## 8. 查询字段和导入的关系

`searchable` 只控制业务数据页面是否显示该字段的精确查询框。

导入时：

- `searchable=1` 不代表必填。
- `searchable=0` 不影响导入。
- 导入后，关键字搜索会匹配业务编码和 `search_text`。
- 字段精确查询只对启用了查询的字段生效。

## 9. 常见失败原因

| 现象 | 可能原因 | 处理方式 |
|------|----------|----------|
| 提示没有工作表 | Excel 文件为空或损坏 | 重新下载模板并填写 |
| 提示没有数据行 | 只有表头，没有有效数据 | 至少填写一行 |
| 提示找不到主键字段列 | 表头被改名或删除 | 使用系统导出的模板 |
| 某行提示必填 | 必填字段为空 | 补齐该行数据 |
| 某行提示组合已存在 | `is_unique` 字段组合重复 | 修改唯一性字段值 |
| 上传失败 | 文件不是 `.xlsx` 或超过 5MB | 使用 `.xlsx` 并控制文件大小 |

---

## 10. 验证建议

导入前：

1. 先在测试环境或本地环境验证。
2. 使用系统导出的模板，不手工新建表头。
3. 少量数据先试导入，确认字段映射正确。

导入后：

1. 在业务数据页面按业务编码查询。
2. 使用已启用查询的字段做精确筛选。
3. 抽查导入数据是否能正常打印。

---

## 11. 测试数据清理

本地测试导入后必须清理本次产生的数据。

只清理明确由测试产生的数据，例如：

- 测试模块导入的 `business_record`
- 测试创建的业务模块
- 测试字段
- 测试模板

不得删除：

- 默认模块：`LOCATION`、`CONTAINER`、`PRODUCT`
- 既有业务数据
- 既有模板
- 生产或本地真实数据

清理规则详见 [测试指南 - 测试数据清理](测试指南.md#测试数据清理强制)。
